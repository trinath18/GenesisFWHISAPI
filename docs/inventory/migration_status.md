# Write-flow migration status

"Migrated" = API + UI + automated tests (rolled back, no data changed) + a browser test against the restored database that restored every touched table to its exact baseline.

Writes MBM, MBMTwo, MBMOthers, MBMOthersTwo, BAT and the maintenance MBMCrossReference (the legacy proc wrote to a separate HISMaintenance database; FWHS data only here). Premium, MCO fee, annual limit and age band come from the shared modules. Slice 2: two-step flow like the legacy form (Membership Header dialog with Last Batch No, then the registration screen with the header fixed and read-only, dates as dd/mm/yyyy) and the Supplementary tab (insured F/H: cover ids 01.., age band per person, supplementary annual limit, MCO and premium by status B/C/D as in saveCoverPersons, written to MBMCoveredPersons and MBMCoveredPersonsTwo). Not yet: lifetime-limit plans, clinic (CIS) plans, payors numbered by policy (none in your data), Others-form extras (weight, height, blood, previous insurer, waiting periods, payor amounts). A sequence number is consumed even if a later step fails, as in the legacy form. |
| Membership > Adjustment | /membership/adjustment | Slice 1 migrated: amendment (type A) of a principal's personal details (MBM, MBMTwo, amend history, MBMCrossReference and renewal-key copies in the maintenance database; name/DOB propagate to the same person's other renewal years).
