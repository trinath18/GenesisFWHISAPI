# Write-flow migration status

"Migrated" = API + UI + automated tests (rolled back, no data changed) + a browser test against the restored database that restored every touched table to its exact baseline.

| Legacy screen | New screen | Status |
|---|---|---|
| Maintenance > Panel Hospital Maintenance | /maintenance/panel-hospitals | Migrated |
| Maintenance > Security > Department | /lookups/department | Migrated (delete refused while users belong to the group) |
| Maintenance > Date | /maintenance/valid-dates | Migrated (adds start <= end checks) |
| Maintenance > Suspension | /maintenance/suspensions, /lookups/suspension-category | Migrated (category delete refused while in use; the legacy form wrote stamp columns that do not exist, the real ones are stamped) |
| Maintenance > MMA | /lookups/mma-procedure, /lookups/mma-fee | Migrated |
| Maintenance > Company Info | - | Not migrated: the `Company` table does not exist in any restored database, so the legacy screen cannot work against this data |
| Membership > Card Sending Mode | /membership/card-sending | Migrated (the legacy "mode <= selected" filter bug is now an equality filter) |
| Membership > MCO Pending | /membership/mco-pending | Migrated (reads FWHS data only; the legacy view also read a separate HISMaintenance database) |
| Membership > Member Reinstatement | /membership/reinstatement | Migrated on the shared fee module (`Genesis.Core/Fees`): rate date and pro-rata start = lapsed date, end = payor expiry, no discounts. Main-database writes are one transaction; the MBMCrossReference copy in the maintenance database is updated afterwards (idempotent; the screen warns if that step fails) |
| Fee module (premium, MCO fee, pro-rata, rounding, discounts) | Genesis.Core/Fees, Infrastructure/Fees | Done and unit tested with hand-computed values; reused by Reinstatement and next by Membership Adjustment. Note: the restored PRM table has no rows for plans FH01/FH11, so results could not be compared with stored real premiums |
| Membership > Adjustment | /membership/adjustment | Slice 1 migrated: amendment (type A) of a principal's personal details (MBM, MBMTwo, amend history, MBMCrossReference and renewal-key copies in the maintenance database; name/DOB propagate to the same person's other renewal years). Slice 2 migrated: cancellation (type C) of a principal: status C, cancel date, covered persons cancelled, amend history, refund row (MBMRefund) from the shared refund module (`Genesis.Core/Fees/Refunds.cs`; the premium formula matches real 2009 refund rows, the MCO refund follows the current VB6 source, which counts the cancel date as covered, one day more than the 2009 rows). Insurer F/H plans whose MCO table charges supplementary persons (status other than A) are refused with a message. Slice 3 migrated: plan change (type P), replicating the legacy form exactly: age band of the new plan (legacy GetAge/GetAgeBand quirks included), fees of the new plan on the payor period with discounts, member status P, new plan/age band/premium/MCO fee (optionally the annual limit), amend history P, MCOPending bordx date, and a refund row computed on the NEW premium and MCO fee from the endorsement date. Not supported: members with covered persons (supplementary fee rules), same-plan changes, dates outside the payor period (the legacy form allowed those). Not yet: suspension, supplementary persons, fee recalculation, lifetime limits, refunds, MBMOthers fields (these use the fee module) |
| Membership > Deletion | /membership/deletion | Migrated with extra safety: preview first, confirmed count typed by the user, max 500 members per request, members with cases or billing records refused, full record written to the audit log before any change, archive copy in FWHSHISARC (status D). Like the legacy form it leaves MBMTwo and other member-detail tables untouched |
| Maintenance > Entity, Case, Benefits, Member, User Permission | - | Later (large) |
